# 통합 보고서 템플릿과 산출물 디렉터리 규약

CEO가 Phase 6에서 읽는다. 보고서는 `work/company/<slug>/report.md`에 저장한다.

## 1. 디렉터리 규약

```
work/company/<YYYY-MM-DD>-<slug>/
├── 00-brief.md            # Phase 1 킥오프 메모
├── briefs/
│   ├── strategy.md        # 부서별 업무지시서
│   └── finance.md
├── strategy.md            # 부서 산출물 (파일명 = 부서 id)
├── finance.md
├── specialized.md
├── assets/                # 표, 이미지, 목업, 코드 조각 등 부속 파일
│   ├── unit-economics.xlsx
│   └── landing-mockup.html
└── report.md              # 통합 보고서 (인덱스 겸용)
```

- slug 규칙: 영문 소문자와 하이픈만, 30자 이내, 주제를 알아볼 수 있게. 예: `used-gear-app`, `pilates-studio-seoul`.
  날짜를 앞에 붙여 디렉터리명을 만든다. 예: `2026-09-10-used-gear-app`.
- 부서 산출물 파일명은 부서 id와 일치시킨다. 같은 부서를 두 웨이브에 부르면 `<id>-2.md`를 쓴다.
- 부속 파일은 `assets/`에 둔다. 보고서 본문에 큰 표나 코드를 붙이지 말고 링크한다.
- 실제로 배포될 코드는 `work/` 안이 아니라 저장소의 정상 경로에 만든다. `work/`는 작업 기록용이다.

### 민감정보 주의

`work/`는 커밋 대상이다. 여기에 쓴 것은 저장소 히스토리에 남는다.

- 자격증명, 토큰, API 키, 비밀번호를 적지 않는다.
- 실명, 연락처, 주민등록번호, 계좌번호 등 개인정보를 적지 않는다. 필요하면 익명화한다.
- 커넥터로 읽은 사용자 데이터는 원문을 옮기지 말고 집계·요약만 남긴다.
- 저장 후 `git diff --check`로 줄 끝 공백을 확인한다.


## 3. 작성 규칙

- 1절 결론은 5줄이다. 길어지면 사용자가 결론을 못 찾는다. 판단(진행/조건부/보류)을 첫 줄에 쓴다.
- 4절은 부서 보고서를 옮겨 붙이는 곳이 아니다. 핵심 1~2줄과 파일 경로만 남긴다.
- 5절 결정 기록은 충돌이 없었어도 "충돌 없음"이라고 적는다. 빈 절은 검토를 안 한 것처럼 보인다.
- 돈, 법률, 의료에 걸리는 항목은 7절 "검토 필요" 열에 표시하고 어떤 전문가 확인이 필요한지 적는다.
- 추정 숫자에는 "추정"과 계산 근거를 붙이고, 외부 사실에는 출처 URL을 붙인다.
- 산출물이 코드나 디자인이면 그 파일이 1급 산출물이다. report.md는 인덱스 역할로 짧게 유지한다.
- 사용자에게 보내는 메시지는 보고서 전문이 아니라 1절, 4절 요약, 5절, 8절, 파일 경로 순으로 압축한 것이다.
