# 브리프 템플릿 (부서 업무지시서)

CEO가 Phase 3에서 부서마다 하나씩 쓴다. 저장 경로는 `work/company/<slug>/briefs/<dept>.md`다.

브리프 전문을 Agent 호출 prompt에 그대로 붙여 넣어라. 서브에이전트는 이 대화를 볼 수 없다.
"위에서 말한 대로"나 "앞의 결론을 참고해"는 서브에이전트에게 아무 의미가 없다.

## 템플릿

```markdown
# 브리프: <부서 한국어명> (<id>) - 프로젝트 <slug>

## 배경 (CEO 메모 요약 5줄)
- 아이디어:
- 목적:
- 대상:
- 제약(예산·기간·지역·기술):
- 이번 프로젝트에서 이 부서의 위치:

## 이 부서가 답할 질문 (최대 3개)
1.
2.
3.

## 수집할 정보 (체크리스트)
내부
- [ ]
외부
- [ ]
다른 부서로부터
- [ ]

## 사용 가능한 도구·플러그인 (tooling 확인 결과)
- 확인함: ListPlugins 결과 <활성 플러그인> 사용 가능, <미설치 플러그인> 없음
- 대체 경로: <WebSearch/WebFetch/xlsx 등>
- 커넥터: <연결됨 / 미연결이면 공개 정보 기반으로 진행>

## 첨부: 다른 부서 산출물 (경로)
- work/company/<slug>/<dept>.md : <3줄 요약>

## 산출물 형식과 저장 경로
- 파일: work/company/<slug>/<id>.md
- 부속 파일: <xlsx/HTML/코드 경로, 없으면 "없음">
- 첫 절은 "요약(10줄 이내)", 마지막 절은 "미해결 질문·가정"
- 최종 메시지로 돌려줄 것: 요약 10줄 + 저장한 파일 경로 + 미해결 질문

## 제약과 하지 말 것
- 다른 서브에이전트를 부르지 않는다(깊이 1).
- 다른 부서의 영역을 대신 결론짓지 않는다. 필요하면 "미해결 질문"으로 넘긴다.
- 출처 없는 숫자를 쓰지 않는다. 계산값에는 "추정"과 계산 근거를 붙인다.
- 사용자 승인 없는 외부 실행(메일 발송, CRM 쓰기, 광고 집행, push)은 하지 않는다.
- <이번 건 특유의 금지사항>

## 마감/범위
- 웨이브: <1|2|3>
- 분량 상한: 본문 <N>줄
- 조사 깊이: <출처 N개 이상 / 시간 상한>
```

## 작성 규칙

- 질문은 3개까지다. 늘리면 답이 얕아진다. 4번째 질문이 떠오르면 다른 부서 몫인지 먼저 의심하라.
- 체크리스트는 해당 부서 reference의 3절에서 발췌하고 이번 건에 맞게 더하고 뺀다. 전체 복사는 하지 마라.
  필요 없는 항목이 섞이면 에이전트가 거기부터 판다.
- 첨부는 경로만 주지 말고 3줄 요약을 함께 적는다. 에이전트가 파일을 읽더라도 무엇을 볼지 알아야 한다.
- "하지 말 것"에는 이번 건 특유의 금지를 최소 1개 넣는다. 예: "경쟁사 유료 데이터는 인용하지 않는다",
  "의료 효능 주장을 쓰지 않는다".
- 분량 상한을 반드시 적는다. 상한이 없으면 보고서가 길어지고 교차 검토가 어려워진다.
- 같은 부서를 두 웨이브에 부를 때는 브리프를 나누고 2차 브리프에 1차 산출물을 첨부한다.
  파일명은 `<dept>.md`, `<dept>-2.md`로 구분한다.

## 채운 예시 (일부)

```markdown
# 브리프: 재무팀 (finance) - 프로젝트 2026-09-10-used-gear-app

## 배경 (CEO 메모 요약 5줄)
- 아이디어: 국내 중고 등산장비 거래 앱
- 목적: 창업 타당성 검증
- 대상: 20~40대 수도권 등산 입문자
- 제약: 기간 6개월, 초기 예산 3천만원, 개발 인력 1명(가정)
- 이번 프로젝트에서 이 부서의 위치: 진행 여부를 가르는 숫자 근거를 낸다

## 이 부서가 답할 질문 (최대 3개)
1. 거래 수수료 몇 %에서 단위경제가 성립하는가.
2. 3천만원으로 몇 개월을 버티며 손익분기 거래액에 도달할 수 있는가.
3. 중고 거래 앱의 통상 결제·정산 비용 구조에서 빠지기 쉬운 비용은 무엇인가.
```
