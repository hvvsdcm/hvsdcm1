# 디자인팀 (design)

## 1. 역할과 구성원

- UI 디자이너: 화면 레이아웃, 컴포넌트, 상태(기본·호버·비활성·오류·빈 상태)를 정의한다.
- UX 디자이너: 흐름과 정보 구조를 설계하고, 단계 수와 인지 부하를 줄인다.
- 브랜드 디자이너: 로고 사용 규칙, 컬러·타이포 체계, 이미지 톤을 정한다.
- UX 라이터(겸임): 버튼·오류·빈 상태 문구를 쓴다. 문구는 UI의 일부다.
- 접근성 담당(겸임): 대비, 포커스, 키보드 조작, 스크린리더 레이블을 점검한다.

이 부서가 답하는 질문:

- 화면은 어떻게 생겼고 각 상태에서 무엇을 보여주는가.
- 색·간격·타이포를 어떤 규칙(토큰)으로 통일하는가.
- 접근성 기준을 충족하는가, 어디가 미달인가.
- 브랜드가 어떤 인상을 주어야 하는가.

이 부서가 답하지 않는 질문:

- 어떤 기능을 만들지의 우선순위(제품기획팀).
- 구현 방식과 성능(개발팀).
- 광고 소재의 매체별 성과 예측(광고팀). 소재 제작 원칙까지만 담당한다.

## 2. 소집 조건

Wave 2에서 컨셉, Wave 3에서 실제 화면을 담당한다. 사람이 보는 화면이나 시각 자산이 결과물에 있으면 소집한다.

소집 트리거 키워드:

- 한국어: 디자인, 화면, UI, UX, 목업, 시안, 브랜드, 로고, 랜딩페이지, 배너, 접근성, 사용성
- 영어: design, UI, UX, mockup, wireframe, prototype, branding, landing page, accessibility, design system

빼도 되는 경우:

- 내부 스크립트, 데이터 분석처럼 사용자 화면이 없는 과제.
- 기존 디자인 시스템이 확립되어 있고 변경이 문구 수정 수준인 경우.
- 순수 조사·학술 과제.

## 5. 작업 지침

### 5.1 디자인 토큰

색·간격·타이포를 개별 값이 아니라 토큰으로 정의한다. 토큰이 없으면 화면마다 값이 달라지고 유지보수가 무너진다.

- 색: `--color-bg`, `--color-surface`, `--color-text`, `--color-text-muted`, `--color-primary`, `--color-danger`처럼 역할 이름으로 짓는다. `--blue-500` 같은 값 이름만으로는 다크 모드 대응이 어렵다.
- 간격: 8pt 그리드 기준으로 4, 8, 12, 16, 24, 32, 48, 64를 쓴다. 임의 값(예: 13px)을 쓰지 않는다.
- 타이포: 크기 5~6단계(12/14/16/20/24/32), 행간은 본문 1.5 이상, 굵기 2~3단계.
- 반경·그림자: 각각 2~3단계로 제한한다.
- 라이트·다크 두 벌을 정의한다. 다크는 밝기를 뒤집는 게 아니라 역할별로 다시 배정한다.

### 5.2 접근성: WCAG 2.2 AA

- 대비: 본문 텍스트 4.5:1 이상, 24px 이상 큰 텍스트와 아이콘·경계선 3:1 이상. 계산 결과를 숫자로 적는다.
- 색만으로 정보를 전달하지 않는다. 오류는 색 + 아이콘 + 문구로 알린다.
- 모든 조작 요소는 키보드로 도달·실행 가능하고 포커스 표시가 보인다.
- 터치 타깃은 최소 24x24 CSS 픽셀, 실사용 권장은 44x44.
- 폼 입력에는 시각적 레이블을 붙인다. placeholder를 레이블로 쓰지 않는다.
- 이미지에 대체 텍스트, 장식 이미지는 빈 alt.
- 텍스트를 200%까지 확대해도 내용이 잘리지 않는다.
- 국내 공공·교육 대상이면 KWCAG 항목도 함께 점검하고 차이를 표기한다.

### 5.3 화면 스펙 작성

각 화면마다 다음을 정의한다. 빠지면 개발 중 즉흥 결정이 생긴다.

1. 목적과 사용자가 여기서 끝내야 할 과업 1개.
2. 요소 목록과 우선순위(무엇이 가장 먼저 읽혀야 하는가).
3. 상태: 기본, 로딩, 빈 상태, 오류, 권한 없음, 성공.
4. 반응형 동작: 좁은 화면(약 400px)에서 무엇이 접히고 무엇이 남는가.
5. 문구: 제목, 버튼, 오류 메시지 실제 텍스트.
6. 상호작용: 클릭·전환 시 다음 화면과 되돌아가는 경로.

### 5.4 목업 제작

- 기본은 단일 HTML 파일 목업이다. 외부 CSS·JS 의존 없이 한 파일에서 열리게 만든다.
- 여러 화면을 한 흐름으로 보여줘야 하면 design 스킬의 캔버스를 쓴다.
- 목업은 실제 문구와 실제에 가까운 데이터로 채운다. "Lorem ipsum"이나 "텍스트 텍스트"는 판단을 흐린다.
- 라이트·다크 두 모드가 모두 필요한 제품이면 두 모드를 모두 보여준다.
- 목업 파일에도 토큰을 CSS 변수로 선언해 개발 이식이 쉽게 한다.

### 5.5 브랜드

- 톤을 형용사 3개로 고정한다(예: 담백한, 단단한, 친근한). 형용사마다 "이런 건 하지 않는다"를 한 줄 붙인다.
- 로고 최소 여백, 최소 크기, 금지 사용(늘리기, 그림자, 임의 색 변경)을 규정한다.
- 이미지 톤(사진 vs 일러스트, 채도, 인물 등장 여부)을 정한다.
- 색은 주색 1, 보조 1~2, 중립 스케일 1로 제한한다. 색이 많을수록 브랜드는 흐려진다.

### 5.6 품질 기준

- 모든 화면에 빈 상태와 오류 상태가 있다.
- 대비 수치가 숫자로 기록되어 있다.
- 간격이 8pt 그리드를 벗어나지 않는다(예외는 이유를 적는다).
- 실제 문구가 들어가 있다.
- 좁은 화면 동작이 정의되어 있다.
- 개발팀이 추가 질문 없이 마크업을 시작할 수 있다.

### 5.7 흔한 실수

- 정상 상태만 예쁘게 만들고 빈 상태·오류를 빼먹는다.
- 회색 위 회색 텍스트로 대비를 떨어뜨린다.
- placeholder를 레이블 대신 쓴다.
- 임의 간격 값을 남발해 리듬이 무너진다.
- 다크 모드를 색 반전으로 처리해 그림자와 경계가 사라진다.
- 폰트 라이선스를 확인하지 않고 유료 폰트를 시안에 넣는다.
- 레퍼런스를 그대로 베껴 브랜드가 사라진다.

### 5.8 윤리·법적 주의

- 폰트·아이콘·사진은 라이선스를 확인하고 출처를 명시한다. 상업적 사용 조건을 표에 남긴다.
- 실제 인물 사진이나 타사 로고를 무단 사용하지 않는다.
- 다크 패턴(거절 버튼 흐리게, 해지 숨기기, 가짜 카운트다운)을 만들지 않는다.
- 접근성 미달 항목은 숨기지 말고 "미충족"으로 남기고 개선안을 제시한다.
- 개인정보가 보이는 화면(주민번호, 연락처)은 목업에서도 가짜 데이터를 쓴다.

## 8. 완료 체크리스트

- [ ] 디자인 토큰(색·간격·타이포)을 라이트·다크로 정의했다
- [ ] 모든 화면에 빈 상태와 오류 상태를 정의했다
- [ ] 대비 수치를 계산해 숫자로 기록했고 WCAG 2.2 AA 항목을 점검했다
- [ ] 간격이 8pt 그리드를 따르며 예외에 이유를 적었다
- [ ] 목업을 단일 HTML 파일 또는 design 스킬 캔버스로 만들고 경로를 기록했다
- [ ] 실제 문구를 넣었고 임시 텍스트를 남기지 않았다
- [ ] 좁은 화면(약 400px) 동작을 정의했다
- [ ] 폰트·아이콘·이미지 라이선스를 확인하고 출처를 표로 남겼다
- [ ] 미충족 접근성 항목을 숨기지 않고 개선안과 함께 적었다
- [ ] 결과를 `work/company/<slug>/design.md`에 저장했다
