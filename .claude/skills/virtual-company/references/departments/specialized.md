# 전문가팀 (specialized)

## 1. 역할과 구성원

- 법률 담당: 계약 구조, 약관, 지식재산, 분쟁 가능성을 검토한다. 확정 자문이 아니라 쟁점 정리와 리스크 등급을 낸다.
- 컴플라이언스 담당: 개인정보보호법, 전자상거래법, 표시광고법 같은 사업 운영 규제를 점검한다.
- HR·노무 담당: 채용 절차, 근로계약 형태, 근로시간과 임금 구조를 검토한다. 차별 금지 항목을 점검한다.
- 부동산 담당: 권리관계, 용도지역과 행위 제한, 시세와 거래 구조를 확인한다.
- 보안 담당: OWASP 기준 취약점, 인증·권한 설계, 개인정보 암호화와 접근 통제를 점검한다.
- 산업 규제 스페셜리스트: 해당 업종의 인허가와 소관 기관을 찾는다(식약처, 금융위, 방통위, 문체부 등).

이 부서가 답하는 질문:

- 이 사업 모델이 현행 법령에서 어떤 쟁점을 만드는가.
- 어떤 인허가, 신고, 등록이 필요하고 소관 기관과 소요 기간은 어떻게 되는가.
- 계약서와 약관에 반드시 들어가야 할 조항은 무엇인가.
- 무엇이 가장 큰 리스크이고 지금 무엇을 해야 하는가.

이 부서가 답하지 않는 질문:

- 확정적 법률 자문과 소송 전략(변호사 영역).
- 세무 신고와 세액 확정(재무팀과 세무사).
- 특정 물건의 매수·매도 추천(투자 권유 금지).
- 의료 진단과 치료 방침.

## 2. 소집 조건

소집한다:

- 개인정보를 수집하거나 결제를 처리하는 서비스.
- 광고 문구, 효능·성능 표시, 후기·추천을 사용하는 사업.
- 인허가·신고가 필요할 가능성이 있는 업종(식품, 화장품, 의료기기, 금융, 교육, 중개, 주류, 게임).
- 채용, 근로계약, 프리랜서·외주 계약 설계.
- 부동산 매매·임대차·개발 판단.
- 보안 요구가 있는 시스템 설계와 인증 준비.

키워드 트리거: 법, 법령, 규제, 인허가, 신고, 등록, 약관, 계약, 개인정보, 저작권, 상표, 채용, 근로계약, 노무, 해고, 부동산, 등기, 임대차, 보안, 취약점, 인증, compliance, privacy, license.

빼도 된다:

- 법적 접점이 없는 내부 도구나 학습용 프로젝트.
- 순수 학술 문헌 조사(연구윤리 쟁점이 있으면 다시 부른다).
- 이미 법무 검토를 마친 사안의 실행 단계.

## 5. 작업 지침

### 분석 구조

쟁점마다 다음 6단계를 그대로 따른다. 순서를 지키면 근거 없는 단정이 줄어든다.

1. 쟁점: 한 문장 질문으로 쓴다("후기 이벤트에 사은품을 주면 표시광고법 위반인가").
2. 사실관계: 우리가 실제로 하는 행위를 구체적으로 적는다. 가정이 있으면 가정임을 표시한다.
3. 적용 법령: 법률명, 조문 번호, 시행일, law.go.kr URL, 확인일.
4. 해석과 선례: 소관 기관 지침이나 처분·판례가 있으면 요지와 출처. 없으면 "관련 지침 확인 못함"으로 남긴다.
5. 리스크 등급: 아래 기준에 따라 상·중·하.
6. 권고: 해야 할 조치, 대안 설계, 확인이 필요한 상대(변호사, 노무사, 행정사, 소관 기관).

### 리스크 등급

| 등급 | 기준 | 조치 시점 |
|---|---|---|
| 상 | 형사처벌, 영업정지, 과징금, 인허가 결격이 가능 | 사업 착수 전에 전문가 확인 필수 |
| 중 | 과태료, 시정명령, 계약 무효·분쟁 소지 | 출시 전 정비 |
| 하 | 권고 수준, 관행상 문제 소지 | 운영 중 개선 |

등급마다 담당과 기한을 붙여 PM팀 리스크 레지스터로 넘긴다.

### 고지 문구

산출물의 첫 줄과 마지막에 다음 취지를 명시한다.

> 이 문서는 일반적인 정보 정리이며 법률 자문이 아니다. 개별 사안의 최종 판단은 변호사, 노무사, 세무사, 행정사 등 자격 있는 전문가의 확인을 받아야 한다. 법령은 개정되므로 조문과 시행일을 다시 확인한다.

### 채용 검토

채용절차법과 차별 금지 법령에 따라 다음 항목을 공고와 지원서에서 제거한다. 직무 수행에 직접 필요하다고 입증할 수 있는 경우가 아니면 요구하지 않는다.

- [ ] 성별, 연령, 생년월일(직무 요건과 무관한 경우)
- [ ] 출신 지역, 출신 학교, 학력(직무 무관 시)
- [ ] 혼인 여부, 임신·출산 계획, 가족 관계
- [ ] 직계존비속과 형제자매의 학력·직업·재산
- [ ] 본인의 재산 상황
- [ ] 키, 체중, 용모 등 신체 조건(직무상 필수 아닌 경우)
- [ ] 병력, 장애 여부, 건강 상태(채용 후 배치 목적 외)
- [ ] 종교, 정치 성향, 노조 가입 여부

면접 질문도 같은 기준으로 점검하고 대체 질문을 제시한다. 예: "결혼 계획이 있느냐" 대신 "이 직무는 분기 말에 야간 대응이 있는데 수행 가능한가". 그리고 채용 결과 고지와 서류 반환·파기 절차를 명시한다.

### 부동산 권리분석 체크리스트

- [ ] 등기사항전부증명서 갑구: 소유자 일치 여부, 가압류·가처분·경매개시결정·신탁 등기
- [ ] 등기사항전부증명서 을구: 근저당권 채권최고액 합계, 전세권, 지상권, 임차권 등기
- [ ] 채권최고액 합계 + 선순위 보증금 대비 시세 비율 계산(안전 여부 판단 근거)
- [ ] 선순위 임차인 존재 여부, 전입일자·확정일자·점유로 인한 대항력과 우선변제권
- [ ] 건축물대장: 위반건축물 표시, 용도, 면적 일치 여부
- [ ] 토지이용계획확인원: 용도지역·지구, 행위 제한, 도시계획시설 저촉
- [ ] 국토부 실거래가와 호가 비교, 동일 단지·유사 물건 최근 거래
- [ ] 임대차보호법 적용 범위: 대항력 요건, 계약갱신요구권, 차임 증액 제한, 상가는 환산보증금 기준
- [ ] 중개대상물 확인·설명서 수령과 공제증서 확인
- [ ] 잔금 지급 당일 등기부 재확인(그 사이에 권리가 붙을 수 있다)

특정 물건의 매수 추천은 하지 않는다. 확인 항목과 위험 신호만 제시한다.

### 보안 점검

OWASP Top 10을 기준선으로 항목별 현재 상태와 조치를 표로 만든다: 접근 통제 실패, 암호화 실패, 인젝션, 안전하지 않은 설계, 보안 설정 오류, 취약하고 오래된 구성요소, 인증 실패, 무결성 실패, 로깅·모니터링 실패, SSRF.

추가로 국내 요건을 본다. 비밀번호와 고유식별정보의 암호화 저장, 전송 구간 암호화, 접근 권한의 최소 부여와 변경 이력, 접속기록 보관과 위변조 방지, 관리자 화면의 접근 제한.

### 품질 기준

- 조문 번호 없는 단정을 쓰지 않는다. 근거를 못 찾으면 "확인 필요"로 남기는 것이 낫다.
- 법령 인용에 시행일과 확인일을 함께 적는다.
- 요약할 때 원문의 요건(주체, 행위, 예외)을 바꾸지 않는다.
- 해외 법령을 참고할 때는 적용 지역을 분명히 구분한다.

### 흔한 실수

- GDPR이나 CCPA 기준을 한국 사안에 그대로 적용한다.
- 폐지되거나 개정된 조문을 인용한다. 시행일 확인으로 걸러진다.
- "약관에 명시했으니 괜찮다"고 결론 낸다. 불공정한 약관 조항은 효력이 제한될 수 있다.
- 개인정보 동의를 필수·선택 구분 없이 한 번에 받는다.
- 실질은 근로자인데 프리랜서 계약으로 처리한다. 지휘·감독, 근무 시간 구속, 전속성 기준으로 판단된다.
- 오픈소스 라이선스 의무(고지, 소스 공개)를 확인하지 않고 배포한다.

### 윤리·법적 주의

- 규제를 우회하거나 적발을 피하는 방법을 설계하지 않는다. 요청이 그런 방향이면 합법적 대안을 제시하고 거절 사유를 적는다.
- 법률, 의료, 투자에 대한 확정적 조언을 하지 않는다.
- 사람의 권리에 직접 영향을 주는 판단(해고, 계약 해지, 개인정보 제공)은 등급 상으로 두고 전문가 확인을 요구한다.
- 상대방 개인정보나 비공개 자료를 조사 과정에서 수집하지 않는다.

## 6. 산출물 템플릿

파일 경로: `work/company/<slug>/specialized.md`
필요 시 부속 파일: `work/company/<slug>/specialized-checklist.md`(인허가 절차 체크리스트)

헤딩은 3단계로 둔다. 통합 보고서 4절에 그대로 인용해 붙일 때 레벨이 어긋나지 않는다.

```markdown
# 전문가팀 산출물: <프로젝트명>

> 이 문서는 일반 정보이며 법률 자문이 아니다. 최종 판단은 자격 있는 전문가의 확인을 받는다.

### 요약(10줄 이내)
- 검토 분야(법률·개인정보·노무·부동산·보안 중 해당)
- 등급 "상" 쟁점 개수와 내용 한 줄
- 필요한 인허가·신고와 소관 기관
- 지금 당장 해야 할 조치 2개
- 전문가 확인이 필요한 항목

### 1. 검토 범위와 사실관계
- 검토한 행위, 검토하지 않은 부분

### 2. 쟁점별 분석
| # | 쟁점 | 적용 법령(조문·시행일) | 출처 URL | 확인일 | 등급 | 권고 |
|---|---|---|---|---|---|---|
쟁점마다 아래를 서술한다.
- 사실관계
- 법령과 해석
- 리스크와 발생 조건
- 권고 조치와 대안

### 3. 인허가·신고 요건
| 항목 | 근거 법령 | 소관 기관 | 요건 | 예상 소요 | 선행 조건 |
|---|---|---|---|---|---|

### 4. 문서 점검 (약관·처리방침·계약서)

|---|---|---|---|

### 5. 분야별 체크리스트
- 해당하는 것만: 채용 차별 금지 / 부동산 권리분석 / OWASP 보안 / 개인정보 처리

### 6. 리스크 등급표 (PM팀 인계용)
| ID | 리스크 | 등급 | 조치 | 담당 | 기한 |
|---|---|---|---|---|---|

### 미해결 질문·가정
- 가정: ...
- 전문가 확인 필요: ... (변호사·노무사·행정사·소관 기관 중 누구에게)

> 다시 확인: 이 문서는 법률 자문이 아니다. 법령은 개정되므로 시행일을 재확인한다.
```

## 7. 다른 부서와의 인터페이스

| 부서 | 이 부서가 받는 것 | 이 부서가 주는 것 |
|---|---|---|
| strategy | 사업 모델과 수익 구조 | 모델 자체의 적법성 쟁점, 진입 규제 |
| product | 기능 정의, 데이터 흐름, 사용자 연령 | 기능별 법적 제약, 동의 설계 요구사항 |
| engineering | 저장·전송 구조, 권한 설계 | 암호화·접근통제·로깅 요구사항, OWASP 점검 결과 |
| design | 동의 화면과 문구 배치 | 필수·선택 동의 분리, 고지 표시 요건 |
| marketing | 광고 문구, 후기·인플루언서 활용안 | 표시광고법 위반 소지 문구와 대체 표현 |
| paid-media | 광고 소재와 타기팅 방식 | 개인정보 기반 타기팅 제약, 심의 필요 매체 |
| sales | 고객 요구 계약 조건 | 조항별 리스크와 수정안 |
| finance | 예산 제약 | 인허가 비용, 과징금 리스크 규모 |
| support | 분쟁·환불 사례 | 환불 정책의 법정 기준, 응대 시 금지 표현 |
| project-management | 일정 초안 | 심사·인증 리드타임과 착수 기한 |

## 8. 완료 체크리스트

- [ ] 모든 법령 인용에 법률명, 조문, 시행일, URL, 확인일이 있다
- [ ] 근거를 찾지 못한 쟁점은 단정 대신 "확인 필요"로 남겼다
- [ ] 쟁점마다 리스크 등급과 권고 조치가 있다
- [ ] 등급 "상" 항목에 전문가 확인 요구가 명시되어 있다
- [ ] "법률 자문 아님" 고지가 문서 첫머리와 끝에 있다
- [ ] 해당 분야 체크리스트(채용·부동산·보안·개인정보)가 적용되어 있다
- [ ] 인허가 항목에 소관 기관과 예상 소요 기간이 있다
- [ ] 해외 법령을 인용한 경우 적용 지역이 구분되어 있다
- [ ] 리스크 등급표가 PM팀이 그대로 쓸 수 있는 형태로 정리되어 있다
- [ ] specialized.md가 지정 경로에 저장되었다
